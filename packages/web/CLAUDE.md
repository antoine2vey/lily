# packages/web

The public marketing site and blog at `https://withlily.app`. It is built with TanStack Start on Vite and prerendered to static HTML in `dist/client`. nginx serves that directory with `nginx.conf` (see `Dockerfile`). There is no server at runtime. A route that needs data at request time cannot exist here.

## Commands

Run every command from the monorepo root.

| Command | What it does |
|---|---|
| `bun run --filter=@lily/web dev` | Vite dev server on port 3001 |
| `bun run --filter=@lily/web build` | Prerenders every page, runs the SEO lint over `dist/client`, then the blog gate, which writes `dist/redirects.map` |
| `bun packages/web/scripts/blog-check.ts --strict --verbose` | The blog gate on its own |
| `bun run --filter=@lily/web preview` | Serves `dist/client` with the production nginx config in Docker on port 8088 |
| `bun run --filter=@lily/web tsc` | Typecheck, which also checks that `fr.ts` matches `en.ts` |
| `bun run --filter=@lily/web lint` | Biome |
| `bun packages/web/scripts/seo-check.ts packages/web/dist/client --baseline <old dist>` | Diffs URLs, canonical, hreflang, og, robots and JSON-LD types against an earlier build |
| `bun packages/web/scripts/page-bytes.ts` | Checks the gzipped JS and CSS that each page in its `PAGES` sample loads up front, and the number of scripts, against the budgets at the top of the script. Other pages are not measured. Run it after `build`. CI runs it from `scripts/check-bundle-sizes.sh` |
| `bun packages/web/scripts/lighthouse.ts` | Mobile Lighthouse, three runs per page (`LIGHTHOUSE_RUNS` changes it), against `preview` on port 8088, with the slow 4G and 4x CPU throttling applied in Chrome. Every run pins the browser language, en-US unless `--language=<tag>` names another. The default pages include `/join/<token>` four times, in en-US and fr-FR, for a first visitor and for one with a stored consent choice. The script starts Chrome itself and answers the invite preview call from a local stub, across the throttled network. The SEO budget does not apply to the noindex join page. `--stored-consent` runs the paths it is given as a visitor who already chose. A run takes about a minute per page, and the timing metrics move with the load on the machine. It exits 1 on a budget breach, and 2 when the machine was too slow for it to judge the timing metrics. Set `CHROME_PATH` if Chrome is not in `/Applications` |
| `bun packages/web/scripts/consent-check.ts` | Drives headless Chrome against `preview` on port 8088. It fails when a page contacts Google or holds a Google Analytics cookie before the visitor accepts, or after the visitor refuses. It also fails when the banner shows in any frame of a page whose visitor has already chosen. It needs network access to Google, and drops each Google Analytics hit before it leaves Chrome, so a run sends nothing to the production property. A failure ends with the fix for each kind of problem it found. CI runs it after `calculator-check.ts`, against the same preview |
| `bun packages/web/scripts/hydration-check.ts` | Drives headless Chrome against `preview` on port 8088 over one page per route and locale, taken from `sitemap.xml`, plus `/join` and a `/join/<token>` path. It fails when a page throws or logs an error, does not hydrate, or ends with a title, description or robots meta other than its prerendered HTML holds. It answers the invite preview call itself and blocks any other request that leaves the server. CI runs it after the build. Set `CHROME_PATH` if Chrome is not in `/Applications` |
| `bun packages/web/scripts/calculator-check.ts` | Holds literal results in its `CASES`: the interval, the dim room flag, the total and each factor as whole percentages, and the dry air humidity. It fails when `calculate()` returns other numbers, and when `CASES` loses a dim room, a north or a south window in either hemisphere, a succulent, or either end of the temperature slider. It then drives headless Chrome against `preview` on port 8088 over the calculator in English and French, on two phones and a desktop. It fails when the prerendered HTML lacks the default result, when the page throws or logs an error, when it reports layout shift past `MAX_CLS` by the time it has hydrated, when it is wider than the viewport, and when the page shows other numbers than `CASES`. When a model change moves a number, take the new value from the shared indoor demand functions called directly, never from `calculate()`. CI runs it after `hydration-check.ts`, against the same preview. Set `CHROME_PATH` if Chrome is not in `/Applications` |
| `bun packages/web/scripts/join-check.ts` | Drives headless Chrome against `preview` on port 8088. It pins the browser language to English, then French, and answers the invite preview call itself, once for each invite view, on four phone sizes, the shortest 360x640 and 390x664, and a desktop, with and without a stored consent choice. It measures every run twice, drawn in the fallback font and in Space Grotesk, and fails when the page draws the other one. On the two short phones and the desktop it also sweeps canopy names made of the widest letter in words of every length, and inviter names of every length a username allows, and skips a name that wraps onto as many lines as one it has measured. On the desktop it fails when the inviter line or the name is cut off. A run takes about 4 minutes. If the display goes to sleep during a run, Chrome stops drawing frames and the runs time out, so keep it awake with `caffeinate -d`. It fails when the join page reports any layout shift, when the top edge of the card moves, when the page is wider than the viewport, when the skeleton card is not within 80px of the plain invite preview, and when the consent banner covers the open button. A failure ends with the fix for each kind of problem it found. CI runs it after `consent-check.ts`, against the same preview |

## Layout

- `src/routes/` holds file-based routes. `$locale/route.tsx` validates the locale and injects the site-wide JSON-LD (`SoftwareApplication`, `Organization`, `WebSite`) once. `index.tsx` is the language redirect at `/`. `join.tsx` is the noindex invite page. nginx serves it for every `/join/<token>` path. The `rewrite` in `src/router.tsx` makes the router read such a path as `/join`, so it hydrates the page that was prerendered. Keep it in step with the `/join/` location in `nginx.conf`.
- `src/i18n/en.ts` is the source of truth for every visible string. `fr.ts` is typed against it, so a missing or extra key fails `tsc`. Read strings with `useI18n()` in components and `messagesFor(locale)` in `head()`. Use `fmt` for `{var}` interpolation and `plural` for counts.
- `src/lib/seo.ts` builds the `head()` of every indexable page. It covers the title, description, canonical, en/fr/x-default hreflang, Open Graph, the Twitter card and JSON-LD. `src/lib/page-seo.ts` wraps it for the plain document pages. The noindex `/` and `/join` routes write their head by hand.
- `src/lib/sitemap.ts` is the single list of indexable URLs. The prerender page list in `vite.config.ts`, `sitemap.xml` and the SEO check all derive from it.
- `vite/posts.ts` compiles `content/posts/<locale>/*.mdx` to `{ meta, html }` modules at build time and exposes the per-locale index as `virtual:post-index/<locale>`. `src/lib/post-data.ts` is the only reader in page code. Import it dynamically inside loaders (`await import('@/lib/post-data')`) so the post index stays out of every page's main chunk. The server-only `sitemap.xml` route imports the index statically.
- `src/components/home/` holds the home page sections. The timelapse hero (`src/components/home/Timelapse.tsx`) and the Water All phone (`src/components/home/WaterCombo.tsx`) run their animation engines inside a single `useEffect` and touch the DOM directly. React does not re-render per frame. The other animated sections mount their engines with `useLive()` from `src/components/home/live.ts`. It imports the engine module only when its root comes within 300px of the viewport, so the home's initial JS carries no engine code, and it sets `data-near`, which gates the CSS screenshot backgrounds. Mount a new animated section the same way. `whileVisible()` in the same file runs a loop only while its element is on screen. `home.css` is scoped under `.tlhero` and `.wc`, and `story.css` uses the `.m-` prefix.
- `src/lib/canopy-invite.ts` holds the only API call. The join page posts the token to `canopy-invites/preview` and opens the app with `lily://join/<token>`. `VITE_API_URL` here is the versioned base, `/api/v1` included, because `API_PREFIX` lives behind the main `@lily/shared` entry, which this package does not import.
- `src/routes/$locale/watering-calculator.tsx` is the free watering calculator. `src/lib/watering-calculator.ts` turns the form input into the indoor demand model's input and runs it in the browser, and `src/lib/cities.ts` is the fixed table of cities whose latitude it uses. `src/components/calculator/Calculator.tsx` is the form and the result. The page prerenders the result for the fixed input of `defaultInput()`, so the HTML is the same on every build, and switches to the current month after hydration. Its strings live in the route-local catalog `src/i18n/calculator/`, typed the same way as `en.ts`. The loader returns them, so they reach the component through the loader data and stay out of the shared i18n chunk.
- **Shared code comes through narrow subpaths only.** Page code imports `@lily/shared/indoor-demand` and `@lily/shared/plant-catalog`, never `@lily/shared` itself. The main entry pulls schemas, services and their dependencies into the browser bundle.
- `public/.well-known/` holds the iOS universal link and Android app link files. They must match the bundle IDs and team in `packages/app/app.json`, and CI checks that with `scripts/check-well-known.ts`.
- `public/tl/` holds the hero frames. Regenerate them from a source video with `scripts/tl-frames.sh`.

## Rules

- **Every indexable page calls `seo()`** with a unique title of at most 60 characters and a description of 120 to 160 characters. The SEO lint in `scripts/seo-check.ts` runs in the build. It fails when any page lacks a title. It also fails when an indexable page lacks a description, has a canonical or `og:url` other than its own URL, lacks an en, fr or x-default hreflang, has other than one `h1`, or is missing from the sitemap. A sitemap URL with no page fails it too. JSON-LD is checked only by the `--baseline` diff. In the lint, a title over 60 characters or a description outside 120 to 160 is only a warning. For a post, the blog gate fails the build on the same description range and on a frontmatter title longer than `TITLE_MAX` in `scripts/blog-check.ts`.
- **New static page.** Add the route, add its path to `STATIC_PATHS` in `src/lib/sitemap.ts`, and add its strings to both `en.ts` and `fr.ts`.
- **No hardcoded copy in components.** That includes aria labels and alt text.
- **Displayed prices are hand-written.** The real subscription price is set in the App Store and Google Play. A price change edits the `Pricing` and `Faq` strings in both `en.ts` and `fr.ts`, the `AggregateOffer` JSON-LD in `src/routes/$locale/route.tsx` and `public/llms.txt`. Nothing keeps them in sync.
- **French typography.** Put a no-break space (U+00A0) before `? ! : ;`.
- **Internal links** use `<Link to="/$locale/..." params={{ locale }}>` so the locale prefix is never lost.
- **App Store links carry a campaign token.** A clickable App Store link is `StoreButtons` or `CtaBand` with the `kind` of the page that renders it (`PageKind` in `src/lib/site.ts`, where an interactive tool such as the calculator is `tool`), or `appStoreUrl()` from `src/lib/site.ts` with a `Campaign`, as `src/components/site/JoinInvite.tsx` does with `web-join`. `scripts/seo-check.ts` fails the build on a prerendered App Store link whose `pt`, `mt` or `ct` does not match the page. The JSON-LD, the Smart App Banner and `public/llms.txt` keep the plain URL.
- **Effect** is for pure data work only (Array, Option, Record, DateTime, Schema). There is no Effect runtime in the browser. Keep Effect's `String` module out of the files that `src/routes/__root.tsx` loads on every page (`src/lib/consent.ts`, `src/lib/analytics.ts`, `src/components/site/ConsentBanner.tsx`), and do not import a module that only the root route loads, such as `src/lib/consent.ts`, from `src/components/site/JoinInvite.tsx`. Do not use Effect's `Order` module in page code either. Write a plain comparator, as `byName` in `src/lib/watering-calculator.ts` does. Each of these makes the bundler regroup the chunks, and every page then loads about five more scripts, the blog post index among them. `scripts/page-bytes.ts` fails on that script count. Code that the root and the join page both need goes in `src/i18n/index.tsx`, which every page already shares, as the page locale helpers do. A module that a loader imports dynamically and a component imports statically becomes a chunk of its own, so return such data from the loader instead of importing it in the component. The shared indoor demand model uses `Match` and `DateTime`, so the calculator already costs every page one more script (the bundler runtime split from `Match`) and about 1.5 KB gzipped in the shared `DateTime` chunk.
- **Head data comes from the loader.** `head()` is synchronous, so anything it needs must come from `loaderData`.
- **Phone mockups copy the real app.** Every phone on the site, the hero included, is static and front-facing, with no tilt, bob or incline. It shows real app screens and behaves as the app does, so it never shows UI the app lacks.
- **Route CSS belongs to a component.** Import a stylesheet that one route needs from a component of that route, as `Timelapse.tsx` does for `home.css` and `story.css`. An import in the route file lands in the stylesheet of every page. Keep the two imports in one file and in that order, because `story.css` overrides rules of `home.css` at equal specificity.
- **Lighthouse gates performance work.** After each step, build, run `preview`, then `scripts/lighthouse.ts` on the prerendered pages, and keep every budget in that script green. `scripts/page-bytes.ts` holds the byte budgets.
- **Space Grotesk loads with `font-display: optional`.** `src/styles.css` redeclares the fontsource faces with `optional`, because their hardcoded `swap` lands after first paint and relayouts `/en` for about 170 to 245 ms of TBT (#229). A cold first visit therefore renders the metric-matched "Space Grotesk Fallback" for that page view, so every stack that names "Space Grotesk Variable" must list the fallback next. Going back to fontsource's `@import` brings the TBT breach back.
- **The join card hangs from a fixed top edge.** `src/components/site/JoinInvite.tsx` sets the top offset of the card from the viewport height alone, so an invite view of another height never moves it (#265). Do not center the card on its own height. Below the `sm` breakpoint the offset is smaller, so a tall card keeps its open button above the consent banner (#284). The open button follows the canopy name, ahead of the hint, and below `sm` the mark and the name are smaller. Below `sm` the inviter line is clamped to three lines and the canopy name to three, or to four at a smaller size when it has more than 24 characters, because how a name wraps is not bounded by its length. From `sm` up both show whole, so the bound holds on a phone only. The full text stays in the DOM and in `title`. On a viewport up to 480px wide the banner is tighter (`site.css`). The height above the button is therefore bounded on a phone (the inviter line at most 72px, the name at most 112px), and the button stays above the banner on a 360x640 phone whatever the names are (#321). Do not remove a clamp or add an unclamped line above the button. The card prerenders the copy that does not depend on the invite. Until the invite preview lands, each slot it fills holds a bar with the box of the element that replaces it. CI runs `scripts/join-check.ts` on every pull request.
- **Analytics needs consent.** Nothing from Google loads until the visitor accepts in the consent banner (`src/components/site/ConsentBanner.tsx`). `src/lib/consent.ts` holds the choice, which the browser keeps in local storage for 180 days. The banner is prerendered, so it paints with the page and never becomes a late LCP element. `CONSENT_SCRIPT` in the same file runs in the head before the first paint. It is the only reader of the stored choice. It writes a valid choice, or `ask`, to `<html data-consent>`. A rule in `site.css` shows the prerendered banner only under `ask`, so a stored choice never paints it and a page whose scripts did not run never shows a banner that cannot close. A hydrated banner carries `data-live` and always shows. `src/lib/analytics.ts` then loads Google Analytics from an idle callback after the window `load` event, because loading it earlier starves hydration and competes with the hero bytes. Do not add a preconnect, a tag or a cookie for a third party outside that path. CI runs `scripts/consent-check.ts` on every pull request.
- **The join page follows the browser language from the first paint.** It is one prerendered file for both languages (#281), and its route sets `staticData.prerendersEveryLocale`. The root route then runs `LANG_SCRIPT` from `src/i18n/index.tsx` in the head, which writes the browser language to `<html lang>`. The page prerenders its copy, and the consent banner, once per locale, each copy marked with `data-locale`. A rule in `site.css` shows only the copy that `<html lang>` names. At hydration `usePageLocales` keeps that copy, keyed by locale so its painted nodes stay, and drops the others. Any other page outside a locale, such as the redirect page `/`, renders the banner only once hydrated. Set the flag only on a page whose first paint shows its copy, since each copy adds to the page bytes.

## Blog

The SEO plan, keyword map and editorial rules live in `docs/seo/strategy.md`. Read it before adding or rewriting a post. One post covers one search intent. Improve the existing hub before adding a post that competes with it.

Every post in `content/posts/<locale>/` needs `title`, `description`, `date` (ISO, the day it first went live), `updated` (ISO, last substantive revision), `slug` (equal to the file name, which is the real slug), `category` (`care-guides`, `watering`, `plant-problems`, `pests` or `houseplant-basics`) and `tags`. `redirectFrom` lists old slugs that now return a 301 to this post. Never remove an entry from it. `PostMeta` in `src/lib/posts.ts` validates the fields the site reads. `scripts/blog-check.ts --strict` runs in the build and checks the rest: the slug and dates, EN/FR parity, redirects, internal links, placeholder hosts and mis-encoded characters. `--strict` also fails on the editorial rules of [docs/seo/strategy.md](../../docs/seo/strategy.md): title and description length, the category, a missing `updated`, em dashes, banned AI phrasing, and in French posts English words, a title identical to the English one and regular spaces where French needs a no-break space. It also writes `dist/redirects.map` for nginx. Add every new post in both locales.

A post body is GitHub-flavored markdown despite the `.mdx` extension. `vite/posts.ts` drops raw HTML and does not compile JSX or imports. It turns a `#` heading into an `h2` so the page keeps one `h1`.
